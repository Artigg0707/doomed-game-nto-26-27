## 2. Словарь данных (назначение всех полей)

### 2.1. ResourceData — состояние ресурсов бункера

Сериализуемый класс, хранится в `ResourceManager.resourceData`. Живёт в памяти, не является ScriptableObject.

| Поле | Тип | Назначение | Допустимые значения |
|------|-----|-----------|-------------------|
| `foodCans` | `int` | Количество банок еды на складе | >= 0 |
| `waterBottles` | `int` | Количество бутылок воды на складе | >= 0 |
| `fuelCans` | `int` | Количество канистр топлива | >= 0 |
| `currentDay` | `int` | Номер текущего дня | >= 1 |
| `temperatureLevel` | `int` | Температура в бункере | 0 = критический холод, 1 = холодно, 2 = нормально, 3 = тепло |
| `generatorBroken` | `bool` | Генератор сломан (нельзя включить до ремонта) | true/false |
| `generatorIsOn` | `bool` | Генератор включён (расходует топливо ночью) | true/false |

**Владелец:** `ResourceManager` ( синглтон на сцене).
**Валидация:** ресурсы не уходят ниже 0 (`Consume` возвращает false при нехватке); температура клампится 0–3.

---

### 2.2. GeneratedCharacter — один житель бункера

Сериализуемый класс, хранится в `CharacterManager.characters`.

| Поле | Тип | Назначение | Допустимые значения |
|------|-----|-----------|-------------------|
| `gender` | `Gender` (enum) | Пол персонажа | Male / Female |
| `fullName` | `string` | Имя и фамилия | строка, генерируется из NamePool |
| `age` | `int` | Возраст | `minAge`–`maxAge` из CharaterObject |
| `portrait` | `Sprite` | Портрет для карточки | из профиля CharaterObject, без повторов |
| `health` | `int` | Здоровье | 0–100. При 0 → смерть |
| `morale` | `int` | Мораль | 0–100. При <0 → уходит из бункера |
| `daysWithoutFood` | `int` | Счётчик дней без еды | >= 0, сбрасывается при получении пайка |
| `daysWithoutWater` | `int` | Счётчик дней без воды | >= 0, сбрасывается при получении пайка |
| `receivesFoodToday` | `bool` | Выдана ли еда сегодня | true/false, сбрасывается в `ResetDailyRations` |
| `receivesWaterToday` | `bool` | Выдана ли вода сегодня | true/false, сбрасывается в `ResetDailyRations` |
| `consecutiveFoodDays` | `int` | Дней подряд получает еду | >= 0, используется для восстановления HP |
| `consecutiveWaterDays` | `int` | Дней подряд получает воду | >= 0, используется для восстановления HP |
| `isDead` | `bool` | Персонаж погиб | true/false |
| `isExiled` | `bool` | Персонаж ушёл из бункера (мораль < 0) | true/false |
| `isSecretRevealed` | `bool` | Секрет раскрыт | true/false (зарезервировано, не используется) |
| `traits` | `List<Trait>` | Черты персонажа | 0 или больше, из CharaterObject.availableTraits |
| `description` | `string` | Текстовое описание | генерируется шаблонами в CharacterGenerator |

**Владелец:** `CharacterManager`.
**Создание:** `CharacterGenerator.Generate()`.
**Мутация:** ночные расчёты `DayCycleManager`, пайки `CharacterManager`, опции записи `EventManager`, вылазки `ExpeditionManager`, ремонт `ElectricalPanelController`.

---

### 2.3. NightReportData — ночной отчёт (основная структура передачи данных между ночью и утром)

Сериализуемый класс, создаётся `DayCycleManager.StartNextDay()` каждый вечер.

| Поле | Тип | Назначение |
|------|-----|-----------|
| `completedDay` | `int` | Завершённый день |
| `newDay` | `int` | Новый день (наступает утром) |
| `fuelConsumed` | `bool` | Был ли израсходован 1 канистр топлива |
| `generatorWorked` | `bool` | Работал ли генератор всю ночь |
| `temperatureBefore` | `int` | Температура до ночи |
| `temperatureAfter` | `int` | Температура после ночи |
| `resourceChanges` | `List<string>` | Текстовые изменения ресурсов для отчёта |
| `survivalChanges` | `List<string>` | Состояние каждого жителя (голод, жажда, здоровье) |
| `deaths` | `List<string>` | Имена погибших за ночь |
| `departures` | `List<string>` | Имена ушедших из-за низкой морали |
| `expeditionReturns` | `List<string>` | Результаты возвращения с вылазок |
| `specialEvents` | `List<string>` | Особые события (поломка/ремонт генератора, записи) |
| `morningReportLines` | `List<string>` | Строки из запланированных записок на этот день |
| `HasAnyEvents` | `bool` (вычисляемое) | Есть ли любые события в отчёте |
| `GetSummaryLine()` | `string` (метод) | Итоговая строка для отчёта |

**Владелец:** `DayCycleManager` собирает, `MorningReportPanel` отображает.

---

### 2.4. ExpeditionLocationData — локация вылазки (ScriptableObject)

Создаётся в редакторе через `CreateAssetMenu`, хранится в `Assets/Resources/Expeditions/` и регистрируется в `ExpeditionLocationCatalog`.

| Поле | Тип | Назначение | Допустимые значения |
|------|-----|-----------|-------------------|
| `locationId` | `string` | Уникальный идентификатор локации | строка,例如 "supermarket" |
| `locationName` | `string` | Название локации (отображается в UI) | строка |
| `locationImage` | `Sprite` | Изображение локации | спрайт |
| `description` | `string` | Описание локации | TextArea |
| `riskDescription` | `string` | Текст риска (отображается игроку) | TextArea |
| `durationDays` | `int` | Сколько дней длится вылазка | >= 1 |
| `injuryChancePercent` | `int` | Базовый шанс травмы 0–100 | 0–100 |
| `deathChancePercent` | `int` | Базовый шанс смерти 0–100 | 0–100 |
| `minInjuryDamage` | `int` | Минимальный урон при травме | >= 0 |
| `maxInjuryDamage` | `int` | Максимальный урон при травме | >= minInjuryDamage |
| `minCooldownDays` | `int` | Минимальная перезарядка локации | >= 1 |
| `maxCooldownDays` | `int` | Максимальная перезарядка локации | >= minCooldownDays |
| `possibleRewards` | `List<ExpeditionRewardData>` | Возможные награды | список |

**Владелец:** `ExpeditionManager` читает, `ExpeditionLocationCatalog` хранит ссылки.
**Валидация:** `OnValidate()` проверяет диапазоны процентов, соотношение min/max, >=1 для дней.

### 2.5. ExpeditionRewardData — награда за вылазку

Вложенный сериализуемый класс внутри `ExpeditionLocationData.possibleRewards`.

| Поле | Тип | Назначение | Допустимые значения |
|------|-----|-----------|-------------------|
| `resourceType` | `ExpeditionRewardType` (enum) | Тип ресурса | Food / Water / Fuel |
| `minAmount` | `int` | Минимальное количество | >= 0 |
| `maxAmount` | `int` | Максимальное количество | >= minAmount |

### 2.6. DoorNoteData — записка у двери (ScriptableObject)

Создаётся в редакторе через `CreateAssetMenu`, хранится в `Assets/Resources/`, автозагружается `EventManager` через `Resources.LoadAll<DoorNoteData>("")`.

| Поле | Тип | Назначение | Допустимые значения |
|------|-----|-----------|-------------------|
| `spawnType` | `SpawnType` (enum) | Тип появления | Scheduled (по дню) / Random (по шансу) |
| `title` | `string` | Заголовок записи | строка |
| `text` | `string` | Текст записи | TextArea |
| `triggerDay` | `int` | День срабатывания (для Scheduled) | >= 0 |
| `randomChance` | `int` | Шанс случайного появления 0–100 | 0–100 |
| `morningReportLine` | `string` | Строка для утреннего отчёта | строка |
| `options` | `List<Option>` | Варианты ответа игрока | список от 1 до N |

**Владелец:** `EventManager` загружает и выбирает активную записку каждый день.

### 2.7. DoorNoteData.Option — вариант ответа на записку

Вложенный сериализуемый класс.

| Поле | Тип | Назначение | Допустимые значения |
|------|-----|-----------|-------------------|
| `buttonText` | `string` | Текст кнопки | строка |
| `deltaFood` | `int` | Изменение еды (положительное = получить) | любое целое |
| `deltaWater` | `int` | Изменение воды | любое целое |
| `deltaFuel` | `int` | Изменение топлива | любое целое |
| `deltaMorale` | `int` | Изменение морали всем живым персонажам | любое целое |
| `hpDamage` | `int` | Урон здоровью случайного живому персонажу | >= 0 |
| `spawnCharacterChance` | `int` | Шанс 0–100 создать нового жителя | 0–100 |

**Применение:** `EventManager.ApplyOption(option)` — 즉시 меняет `ResourceManager`, мораль всех, HP случайного, может вызвать `CharacterManager.CreateCharacter()`.

### 2.9. TraitEffect — эффект черты

Вложенный сериализуемый класс.

| Поле | Тип | Назначение | Допустимые значения |
|------|-----|-----------|-------------------|
| `effectType` | `EffectType` (enum) | Тип эффекта | см. ниже |
| `value` | `float` | Значение эффекта | проценты или очки, зависит от типа |
| `locationNumber` | `int` | Номер локации (для CannotGoOnExpeditionToLocation) | >= 1 |

**Перечисление `EffectType`:**
- `FoodConsumptionReductionPercent` — снижение потребления еды %
- `PlumbingBreakChanceChangePoints` — изменение шанса поломки водопровода (очки)
- `ElectricityBreakChanceChangePoints` — изменение шанса поломки генератора (очки)
- `NoInjuryOnGeneratorRepair` — иммунитет к травме при ремонте (флаг)
- `RestHealthRecoveryIncreasePercent` — бонус восстановления здоровья %
- `RestMoraleRecoveryIncreasePercent` — бонус восстановления морали %
- `ExpeditionSuccessChanceChangePoints` — изменение шанса успеха вылазки (очки)
- `CannotGoOnExpeditionToLocation` — запрет вылазки в локацию №N
- `WaterRepairInjuryChanceChangePoints` — изменение шанса травмы ремонта воды (очки)
- `ElectricityRepairInjuryChanceChangePoints` — изменение шанса травмы ремонта электрики (очки)
- `WaterRepairInjuryChanceReductionPercent` — снижение шанса травмы ремонта воды %
- `ElectricityRepairInjuryChanceReductionPercent` — снижение шанса травмы ремонта электрики %
- `CannotRepairWater` — запрет ремонта воды (флаг)
- `CannotRepairElectricity` — запрет ремонта электрики (флаг)
- `InjuryChanceChangePoints` — изменение шанса травмы (очки)
- `CannotBeSpiedOn` — нельзя шпионить (флаг)
- `AvoidNegativeChoices` — избегать отрицательных выборов (флаг)

### 2.10. CommandantCommentSettings — шаблоны комментариев коменданта

ScriptableObject, используется `MorningReportPanel.GetCommandantComment()`.

| Поле | Тип | Назначение |
|------|-----|-----------|
| `deathComments` | `List<string>` | Комментарии при наличии смертей |
| `hungryComments` | `List<string>` | Комментарии при голоде >= 2 персонажей |
| `thirstyComments` | `List<string>` | Комментарии при жажде >= 2 персонажей |
| `injuredComments` | `List<string>` | Комментарии при наличии раненых |
| `hungryAndThirstyComments` | `List<string>` | Комментарии когда 1 голоден и 1 хочет пить |
| `loneComments` | `List<string>` | Комментарии когда ровно 1 человек в каком-то состоянии |
| `calmComments` | `List<string>` | Комментарий когда всё спокойно |

**Логика выбора:** смерти → уходы → голод >=2 → жажда >=2 → раненые → 1+1 → 1 любой → иначе calm.

### 2.13. SurvivalConfig — конфиг выживания и баланса (ScriptableObject)

Единственный конфиг игры. Хранится в `Assets/Scripts/SurvivalConfig.asset`.

| Группа | Поле | Тип | Назначение | Допустимые значения |
|--------|------|-----|-----------|-------------------|
| Победа | `victoryDay` | `int` | День победы | >= 1 |
| Мораль | `baseMoralePenaltyPerDeath` | `int` | Штраф морали за смерть | 0–100 |
| Стартовые ресурсы | `startFoodMin/Max` | `int` | Диапазон банок еды при старте | >= 0, min <= max |
| | `startWaterMin/Max` | `int` | Диапазон бутылок воды при старте | >= 0, min <= max |
| | `startFuelMin/Max` | `int` | Диапазон канистр топлива при старте | >= 0, min <= max |
| Генератор: поломка | `baseBreakdownChancePercent` | `int` | Базовый шанс поломки за ночь % | 0–100 |
| | `breakdownChanceForOnePerson` | `int` | Шанс поломки при 1 человеке в бункере % | 0–100 |
| | `breakdownReductionPerAdditionalPerson` | `int` | Снижение шанса за каждого доп. человека % | 0–100 |
| Генератор: ремонт | `baseRepairSuccessChancePercent` | `int` | Базовый шанс успешного ремонта % | 0–100 |
| | `baseRepairInjuryChancePercent` | `int` | Базовый шанс травмы при ремонте % | 0–100 |
| | `repairFailureDamageHP` | `int` | Урон HP при неудачном ремонте | 0–100 |
| | `repairSuccessBonusPerAdditionalPerson` | `int` | Бонус ремонта за каждого доп. человека % | 0–100 |
| Вылазки | `referencePopulation` | `int` | Базовая численность (без 추가 шансов) | >= 1 |
| | `expeditionDeathChanceIncreasePerMissingPerson` | `int` | +% смерти за missing person | 0–100 |
| | `expeditionInjuryChanceIncreasePerMissingPerson` | `int` | +% травмы за missing person | 0–100 |
| Голод | `hungerPenalties[]` | `List<SurvivalPenaltyRow>` | Штрафы по дням без еды | см. ниже |
| Жажда | `thirstPenalties[]` | `List<SurvivalPenaltyRow>` | Штрафы по дням без воды | см. ниже |
| Холод | `freezingTemperatureThreshold` | `int` | Порог замерзания | >= 0 |
| | `coldDamageAtZero` | `int` | Урон при температуре 0 | >= 0 |
| | `coldDamageLow` | `int` | Урон при температуре 1.. | >= 0 |
| | `coldMoralePenalty` | `int` | Штраф морали от холода | 0–100 |
| Экспедиции | `deathChancePercent` | `int` | Базовый шанс смерти на вылазке % | 0–100 |
| | `minCooldownDays` | `int` | Мин. кулдаун локации | >= 1 |
| | `maxCooldownDays` | `int` | Макс. кулдаун локации | >= 1 |

**Валидация:** `OnValidate()` / `OnEnable()` вызывают `Validate()`, который clamp'ит значения и пишет `Debug.LogWarning` при некорректных данных.

### 2.14. SurvivalPenaltyRow — строка штрафа по дню

Вложенный класс в `SurvivalConfig`.

| Поле | Тип | Назначение |
|------|-----|-----------|
| `day` | `int` | День без ресурса (0, 1, 2, 3, 4…) |
| `moralePenalty` | `int` | Штраф морали |
| `healthDamage` | `int` | Урон здоровью |
| `lethal` | `bool` | Смертельный штраф (HP <= 0 → смерть) |
| `label` | `string` | Текстовая метка для отчёта |

**Логика выбора:** точное совпадение `day` имеет приоритет; иначе самая поздняя подходящая строка (`row.day <= daysWithout`) действует для всех последующих дней.

### 2.15. Stati / HiddenStatDefinition / disease — неиспользуемые заготовки

Эти сущности определены, но **не используются в коде** (статус: в разработке / заготовка):

| Сущность | Статус | Примечание |

| `disease.availableDiseases` | Закомментировано | В `CharaterObject` |

## 3. Потоки данных между модулями

### 3.1. Ресурсы ↔ Менеджеры

```
ResourceManager <---> ResourceData (читает/пишет поля)
CharacterManager --> ResourceManager : ConsumeFood/Water при выдаче пайка
ExpeditionManager --> ResourceManager : AddFood/Water/Fuel при награде
EventManager --> ResourceManager : ApplyOption меняет еду/воду/топливо
DayCycleManager --> ResourceManager : ConsumeFuel, AddTemperature, SetTemperature
ElectricalPanelController --> ResourceManager : BreakGenerator, RepairGenerator, SetGeneratorOn
```

### 3.2. Персонажи ↔ Менеджеры

```
CharacterGenerator --> CharaterObject : профиль генерации
CharacterGenerator --> NamePool : генерация имени/фамилии
CharacterGenerator --> Trait : случайная черта при создании
CharacterManager --> GeneratedCharacter : список всех жителей
CharacterManager --> ResourceManager : проверка ресурсов перед пайком
DayCycleManager --> CharacterManager : UpdateSurvivalCounters, ResetDailyRations
EventManager --> CharacterManager : изменение мораль/здоровье/новый житель
ElectricalPanelController --> CharacterManager : выбор кандидата на ремонт
ExpeditionManager --> CharacterManager : жив ли персонаж, не в поездке ли
```

### 3.3. Вылазки ↔ Данные

```
ExpeditionManager --> ExpeditionLocationData : риск, длительность, награды, кулдаун
ExpeditionLocationCatalog --> ExpeditionLocationData : список всех локаций
ExpeditionManager --> NightReportData : expeditionReturns после завершения
```

### 3.4. Записки ↔ Данные

```
EventManager --> DoorNoteData : загружает через Resources.LoadAll
DoorNoteData --> DoorNoteData_Option : варианты ответа с изменениями
DoorNoteData_Option --> ResourceManager : deltaFood/Water/Fuel
DoorNoteData_Option --> CharacterManager : deltaMorale, hpDamage, spawnCharacterChance
DoorNoteData --> NightReportData : morningReportLine, specialEvents
```

### 3.5. Отчёт ↔ Данные

```
DayCycleManager --> NightReportData : собирает все поля за ночь
NightReportData --> MorningReportPanel : источник текста отчёта
MorningReportPanel --> CommandantCommentSettings : шаблон комментария
```

### 3.6. Генератор

```
ElectricalPanelController --> NightReportData : ProcessGeneratorNight добавляет specialEvents
ElectricalPanelController --> GeneratedCharacter : требует персонажа для ремонт
```

## 6. Итог

Схема данных покрывает всю игровую систему:
- **Ресурсы** (`ResourceData`) — единый источник истины, управляется `ResourceManager`.
- **Персонажи** (`GeneratedCharacter`) — полное состояние жителя, мутирует ночью, при пайках, вылазках, событиях.
- **Ночной отчёт** (`NightReportData`) — агрегат результатов ночи, передаётся в утреннюю сводку.
- **Вылазки** (`ExpeditionLocationData`, `ExpeditionRewardData`) — настраиваются через SO-ассеты.
- **Записки** (`DoorNoteData`, `Option`) — события у двери, автозагружаются из `Resources/`.
- **Черты** (`Trait`, `TraitEffect`) — модифицируют генератор, ремонт, вылазки.
- **Баланс** (`SurvivalConfig`) — один конфиг на всю игру: стартовые ресурсы, генератор, вылазки, выживание.
