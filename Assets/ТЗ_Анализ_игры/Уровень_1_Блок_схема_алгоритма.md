# Уровень 1 — Блок-схема алгоритма и архитектурный граф

> Задание ТЗ: «Реализуйте полный центральный цикл от действия игрока до результата. Допустимы жесткие связи модулей и создание объектов во время выполнения. Представьте архитектурный граф, блок-схему алгоритма и схему данных: объясните назначение модулей, входы, результаты, обмен данными и ветвления.»
>
> Игра: «Doomed Game» (Unity, C#). Сцена: `GameScene 1.unity`.

---

## 1. Центральный цикл игры (кратко)

Игрок ходит по бункеру, взаимодействует с объектами мира (дверь с запиской, кровать, рационная доска, электропанель, ПК), меняет состояние ресурсов и жителей, ложится спать. Ночью происходит расчёт выживания (голод, жажда, холод, мораль), итоги вылазок, состояние генератора, события записки. Утром игроку показывается сводка ночи, проверяется победа (день ≥ 10) или поражение (все жители мертвы или ушли). Цикл повторяется.

## 4. Назначение модулей, входы, результаты, обмен данными

### 4.1. Менеджеры (синглтоны на GameObject «Manager»)

| Модуль | Назначение (ответственность) | Входы (зависимости) | Результаты / выходы | Обмен данными | Ключевые ветвления |
|--------|------------------------------|---------------------|---------------------|---------------|--------------------|
| **ResourceManager** | Единый источник истины по ресурсам: еда, вода, топливо, температура (0–3), состояние генератора (сломан / вкл / выкл). | `ResourceData` (сериализуемый класс), `SurvivalConfig` (стартовые ресурсы) | Методы `ConsumeFood/Water/Fuel` (bool), `AddFood/Water/Fuel`, `SetTemperature`, `AddTemperature`, `BreakGenerator`, `RepairGenerator`, `SetGeneratorOn`. Свойства `FoodCans`, `WaterBottles`, `FuelCans`, `TemperatureLevel`, `GeneratorBroken`, `GeneratorIsOn`, `CanTurnOnGenerator`. | Событие `OnResourcesChanged (Action)` | Не даёт уйти ресурсу ниже 0; температура клампится 0–3; генератор нельзя включить, если сломан или нет топлива |
| **CharacterManager** | Управление списком жителей, генерация персонажей, выдача рационов еды/воды, карточки персонажей на UI. | `CharacterGenerator`, `ResourceManager`, `DayCycleManager` | `CreateCharacter()`, `SetFoodRation()`, `SetWaterRation()`, `ResetDailyRations()`, `HasLivingCharacters()`, `SetAllFoodRations()`, `SetAllWaterRations()` | Событие `OnRationsChanged (Action)` | `CanChangeRation` (жив, не в вылазке, в списке); при нехватке ресурса пайк не выдаётся, состояние не ломается |

| **ExpeditionManager** | Вылазки: запуск, кулдауны локаций, исходы (смерть / травма / награды). | `CharacterManager`, `DayCycleManager`, `ResourceManager`, `SurvivalConfig`, `ExpeditionLocationData` (SO) | `TryStartExpedition()`, `ProcessCompletedDay()`, `CompleteExpedition()` | Событие `OnExpeditionsChanged (Action)` | Лимит одновременных вылазок = Alive/2; доступность локации (кулдаун / занята); шанс смерти / травмы зависит от числа людей в бункере |
| **ElectricalPanelController** | Генератор: включение / выключение, поломка ночью, ремонт персонажем, модификаторы черт. | `ResourceManager`, `CharacterManager`, `ExpeditionManager`, `SurvivalConfig`, `Trait` (SO) | `ToggleGenerator()`, `SendCharacterForRepair()`, `ProcessGeneratorNight()` | События `OnResourcesChanged`, `OnGeneratorStatusChanged` | Шанс поломки зависит от числа людей + черт; шанс успешного ремонта и шанс травмы при провале |
| **EventManager** | Записки у двери: запланированные / случайные, применение выбранной игроком опции. | `DayCycleManager.OnDayChanged`, `DoorNoteData` (SO через `Resources.LoadAll`), `ResourceManager`, `CharacterManager` | `ApplyOption(option)` меняет ресурсы, мораль всех, HP случайного, шанс спавна жителя | Прямые вызовы менеджеров | `Scheduled` по `triggerDay` или `Random` по `randomChance`; одна активная записка на день |

**Потоки данных:**
- `ResourceManager` читает/пишет `ResourceData`.
- `CharacterManager` → `ResourceManager` (списание / выдача ресурса при пайке).
- `ExpeditionManager` → `ResourceManager` (награды), → `CharacterManager` (кто на вылазке).
- `EventManager` → `ResourceManager` + `CharacterManager` (эффекты опции записи).
- `DayCycleManager` собирает `NightReportData` от всех систем ночью.

## 6. Подробное описание центрального цикла (пошагово)

### День (игровой цикл)

1. **Инициализация** — при загрузке сцены на GameObject `Manager` просыпаются все синглтоны. `CharacterGenerator` создаёт 5 стартовых персонажей (`GeneratedCharacter`) и рисует их карточки на UI. `ResourceManager` выставляет случайные стартовые ресурсы (еда 8–10, вода 8–10, топливо 4–6, температура 3).
2. **Дневной цикл** — игрок перемещается (`PlayerMove`), камера поворачивается мышью (`CinemachineCursorLook`). `Interactor` каждый кадр делает raycast из камеры под курсором. Если наведен на объект с `IHighlightable` — объект подсвечивается.
3. **Взаимодействие** — при клике ЛКМ `Interactor` вызывает `IInteractable.Interact()` на найденном объекте. Ветвление по типу объекта:
   - **Дверь / записка** — `InteractDoor` проверяет `EventManager.HasActiveNote()`, если да — открывает `DoorNoteUI` с активной запиской. Игрок выбирает опцию → `EventManager.ApplyOption(option)` сразу меняет ресурсы (`ResourceManager`), мораль всех живых (`CharacterManager`), наносит урон HP случайному персонажу, возможно спавнит нового жителя.
   - **Кровать** — `InteractBed` / `BedSleepTrigger` запускает `SleepSequence()`: отключает управление, затухает экран, вызывает `DayCycleManager.StartNextDay()`.
   - **Рационная доска** — открывает `RationMenuUI`. Игрок переключает пайки еды/воды для персонажей. `CharacterManager.SetFoodRation/SetWaterRation` проверяет достаточно ли ресурсов в `ResourceManager`. Если нет — UI показывает сообщение, пайк не выдаётся, состояние не ломается.
   - **Электропанель** — открывает `ElectricalPanelUI`. Игрок может включить / выключить генератор (`ToggleGenerator`) или отправить персонажа на ремонт (`SendCharacterForRepair`).
   - **ПК** — переключает приоритет камеры Cinemachine, открывает привязанную панель (например, список вылазок).
   - **Вылазки** — через `ExpeditionsTabUI` игрок выбирает локацию и персонажа, нажимает «Отправить экспедицию». `ExpeditionManager.TryStartExpedition` проверяет лимиты, кулдауны, состояние персонажа. При успехе создаётся `ExpeditionRun` и персонажу отменяются пайки на сегодня.

### Ночь (StartNextDay)

Сон — точка входа в ночные расчёты. После затухания экрана вызывается `DayCycleManager.StartNextDay()`, который выполняет 8 шагов:

| Шаг | Что происходит | Модули |
|-----|---------------|--------|
| 1 | Топливо и температура: если генератор работал и цел — −1 топливо, +1 температура; иначе −1 температура | `DayCycleManager`, `ResourceManager` |
| 2 | Выживание: для каждого живого персонажа считаются дни без еды/воды, накладываются штрафы мораль/HP, возможная смерть, холодный урон, восстановление HP/морали при пайках ≥2 дней подряд | `DayCycleManager`, `CharacterManager`, `SurvivalConfig` |
| 3 | Сброс пайков: все `receivesFoodToday` / `receivesWaterToday` = false | `CharacterManager` |
| 4 | Экспедиции: уменьшение `daysRemaining`, завершение — проверка смерти/травмы/награды | `ExpeditionManager`, `CharacterManager`, `ResourceManager` |
| 5 | Генератор: шанс поломки ночью, обработка pending ремонта | `ElectricalPanelController`, `ResourceManager`, `CharacterManager` |
| 6 | Мораль и уходы: штраф морали за смерти, уход персонажа если мораль < 0 | `DayCycleManager`, `CharacterManager` |
| 7 | События дня: `EventManager.OnNewDay` выбирает записку на следующий день (запланированную или случайную) | `EventManager`, `DayCycleManager` |
| 8 | Проверка конца игры: `IsDefeat()` (все мертвы/ушли) или `IsVictory()` (день ≥ 10) | `DayCycleManager` |

### Утро

1. `NightReportData` собирается со всеми изменениями за ночь (ресурсы, выживание, смерти, уходы, экспедиции, события).
2. `MorningReportPanel.Show(report)` показывает игроку сводку с текстом, состоянием жителей, комментарием коменданта.
3. После нажатия «Продолжить» экран осветляется, управление возвращается игроку, цикл начинается заново.

### Конец игры

- **Поражение** — `DefeatScreenPanel.ShowDefeatWithStory()`: дни survived, выжило / погибло / ушло, причина. Кнопки: Рестарт (перезагрузка сцены) или Выход.
- **Победа** — `DefeatScreenPanel.ShowVictoryWithStory()`: дни survived, статистика, гуманитарный конвой.

## 7. Ключевые точки ветвления (таблица)

| Точка ветвления | Условие | Ветвь «Да» | Ветвь «Нет» |
|-----------------|---------|------------|-------------|
| Клик по объекту | `Input.GetMouseButtonDown(0)` | Обработка объекта (`InteractObj`) | Продолжение дневного цикла |
| Достаточно ресурсов для пайка | `ResourceManager.ConsumeFood/Water(1)` == true | Пайк выдан, ресурс списан, `OnRationsChanged` | Сообщение «Недостаточно еды/воды», toggle сбрасывается, состояние не ломается |
| Доступность локации для вылазки | `IsLocationAvailable(location)` (не на кулдауне, не занята) | Экспедиция запускается | Предупреждение в UI |
| Лимит вылазок | `ActiveExpeditionCount < MaxConcurrentExpeditions` | Новая вылазка разрешена | Предупреждение «максимум вылазок» |
| Исход вылазки | `RollChance(adjustedDeathChance)` | Смерть персонажа, наград нет | Проверка травмы |
| Исход вылазки (травма) | `RollChance(adjustedInjuryChance)` | Урон HP, возможно смерть | Награды → `ResourceManager.Add*()` |
| Поломка генератора | `RollChance(breakdownChance)` | Генератор сломан (`BreakGenerator`) | Генератор продолжает работать |
| Ремонт генератора | `RollChance(successChance)` | Генератор чинится (`RepairGenerator`) | Проверка травмы при неудачном ремонте |
| Травма при ремонте | `RollChance(injuryChance)` | Урон HP, возможно смерть | Ремонт не удался, без травмы |
| Конец игры | `IsDefeat()` / `IsVictory()` | Поражение или Победа → экран конца игры | Продолжение цикла (утро → день) |
| Комментарий коменданта | Есть ли смерти / уходы / голод / жажда / ранения | Соответствующий шаблон комментария | Спокойный комментарий (`calmComments`) |
