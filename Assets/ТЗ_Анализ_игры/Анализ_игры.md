# Анализ игры «Doomed Game» (Unity)

> Цель документа: полный разбор проекта перед выполнением ТЗ с тремя уровнями сложности (начальный / средний / высший).
> Источник: все `.cs`-скрипты в `Assets/Scripts/`, `Assets/ScriptableObjects/`, сцены `Assets/Scenes/GameScene 1.unity`, ассетов `Assets/Resources/` и существующих документов архитектуры.

---

## 1. Что это за игра

**Жанр:** выживание в бункере (управление ресурсами и людьми, пошаговый дневной цикл).
**Платформа:** Unity (C#), Szenen `GameScene 1.unity`.
**Цель игры:** дожить до дня 10 (победа — гуманитарный конвой). **Поражение:** все жители мертвы или ушли из бункера.

**Центральный цикл игры (игровой цикл):**
```
День: игрок ходит по бункеру → взаимодействует с объектами (дверь/записка, кровать,
рационная доска, электропанель/генератор, ПК/вылазки) → меняет состояние ресурсов
и людей → ложится спать → Ночь: расчёт выживания (голод, жажда, холод, мораль),
экспедиции, поломка/ремонт генератора, события записки → Утро: сводка ночи →
проверка победы/поражения → следующий день.
```

## 2. Модули (менеджеры-синглтоны): назначение, входы, результаты, ветвления

Все менеджеры висят на одном GameObject `Manager` на сцене и доступны через `static Instance`.

| Модуль | Файл | Назначение (ответственность) | Входы (зависимости) | Результаты / выходы | Обмен данными | Ключевые ветвления |
|--------|------|------------------------------|---------------------|---------------------|---------------|--------------------|
| **ResourceManager** | `Scripts/Resources/ResourceManager.cs` | Единый источник истины по ресурсам: еда, вода, топливо, температура (0–3), состояние генерателя (сломан/вкл). | `ResourceData` (сериализуемый класс) | Методы `ConsumeFood/Water/Fuel` (bool), `AddFood/Water/Fuel`, `SetTemperature`, `BreakGenerator`, `RepairGenerator`, `SetGeneratorOn` | Событие `OnResourcesChanged (Action)` | Не даёт уйти ниже 0; температура клампится 0–3; генератор нельзя включить, если сломан или нет топлива |
| **CharacterManager** | `Scripts/Character/CharacterManager.cs` | Список жителей, генерация персонажей, выдача рационов еды/воды, карточки UI. | `CharacterGenerator`, `ResourceManager` | `CreateCharacter()`, `SetFoodRation/SetWaterRation`, `ResetDailyRations()`, `HasLivingCharacters()` | Событие `OnRationsChanged (Action)` | Проверка `CanChangeRation` (жив, не в вылазке, в списке); при нехватке ресурса пайк не выдаётся, состояние не ломается |
| **CharacterGenerator** | `Scripts/Character/CharacterGenerator.cs` | Генерация одного персонажа из профиля `CharaterObject` (имена, пол, возраст, портреты, черта, описание). | `CharaterObject` (SO), `NamePool` (SO), `Trait` (SO) | `GeneratedCharacter` | Прямой вызов `Generate()` | Случайный пол/имя/возраст/портрет; уникальность описания (HashSet) |
| **DayCycleManager** | `Scripts/DayCycleManager.cs` | Оркестратор ночи: переход дня, ночной расчёт выживания, проверка победы/поражения. | Все менеджеры, `SurvivalConfig` (SO), `ResourceData` | `NightReportData`, события `OnDayChanged`, `OnNightComplete`, `OnDefeat`, `OnVictory` | События + прямые вызовы менеджеров | 8 шагов ночи (топливо/температура → выживание → сброс рационов → экспедиции → генератор → мораль/уходы → события дня → конец игры) |
| **ExpeditionManager** | `Scripts/ExpeditionManager.cs` | Вылазки: запуск, кулдауны локаций, исходы (смерть/травма/награды). | `CharacterManager`, `DayCycleManager`, `ResourceManager`, `ExpeditionLocationData` (SO) | `TryStartExpedition()`, `ProcessCompletedDay()`, `CompleteExpedition()` | Событие `OnExpeditionsChanged (Action)` | Лимит одновременных вылазок = Alive/2; доступность локации (кулдаун/занята); шанс смерти/травмы зависит от числа людей в бункере |
| **ElectricalPanelController** | `Scripts/Interaction/ElectricalPanelController.cs` | Генератор: включение/выключение, поломка ночью, ремонт персонажем, модификаторы черт. | `ResourceManager`, `CharacterManager`, `ExpeditionManager`, `Trait` (SO) | `ToggleGenerator()`, `SendCharacterForRepair()`, `ProcessGeneratorNight()` | События `OnResourcesChanged`, `OnGeneratorStatusChanged` | Шанс поломки зависит от числа людей + черт; шанс успешного ремонта и шанс травмы при провале |
| **EventManager** | `Scripts/Door/EventManager.cs` | Записки у двери: запланированные/случайные, применение выбранной игроком опции. | `DayCycleManager.OnDayChanged`, `DoorNoteData` (SO через Resources.LoadAll), `ResourceManager`, `CharacterManager` | `ApplyOption(option)` меняет ресурсы, мораль всех, HP случайного, шанс спавна жителя | Прямые вызовы менеджеров | `Scheduled` по triggerDay или `Random` по randomChance; одна активная записка на день |

### Объекты мира (IInteractable / IHighlightable)
- **Дверь / записка** (`InteractDoor`, `InteractNote`) → открывает `DoorNoteUI` с активной запиской `EventManager`.
- **Кровать** (`InteractBed`, `BedSleepTrigger`) → засыпание → `DayCycleManager.StartNextDay()` → ночь.
- **Рационная доска** (`InteractRationBoard`) → `RationMenuUI.Open()` → распределение пайков.
- **Электропанель** (`InteractElectricalPanel`) → `ElectricalPanelUI.Open()` → генератор/ремонт.
- **ПК** (`InteractPC`) → переключает камеру Cinemachine, открывает привязанную панель (вылазки).

### Ввод и камера
- `Interactor` — raycast из камеры под курсор, вызов `Interact()`, подсветка `Highlight()`.
- `PlayerMove` — перемещение (отключается во время сна).
- `CinemachineCursorLook` — поворот камеры мышью.
- `Quit` — Exit по Esc.

### UI-панели
`MorningReportPanel`, `DefeatScreenPanel`, `RationMenuUI`, `ElectricalPanelUI`, `ExpeditionsTabUI`, `ActiveExpeditionsUI`, `DoorNoteUI`, `CharacterBioPanelUI` + карточки персонажей.

## 3. Схема данных

**Сериализуемые модели (классы, живут в памяти синглтонов):**
- `ResourceData` — `foodCans`, `waterBottles`, `fuelCans`, `currentDay`, `temperatureLevel`, `generatorBroken`, `generatorIsOn`.
- `GeneratedCharacter` — пол, имя, возраст, портрет, здоровье 0–100, мораль 0–100, дни без еды/воды, флаги рационов today, счётчики подряд-дней, `isDead`, `isExiled`, `List<Trait> traits`, `description`.
- `NightReportData` — агрегат ночи: день, температура до/после, списки изменений ресурсов, выживания, смерти, уходы, возвращения экспедиций, особые события.

**ScriptableObjects (данные, настраиваются в редакторе):**
- `ExpeditionLocationData` — локация вылазки: имя, описание, длительность, шансы травмы/смерти, урон, кулдаун, posible награды (еда/вода/топливо).
- `DoorNoteData` — записка: тип появления (Scheduled/Random), день триггера, шанс, заголовок, текст, список опций с дельтами ресурсов/морали/урона/шансом спавна.
- `Trait` — черта с набором эффектов (EffectType + value), модифицирующих генератор, ремонт, вылазки.
- `CharaterObject` — профиль генерации (портреты, пул имён, возраст, черты).
- `NamePool` — имена/фамилии по полу.
- `SurvivalConfig` — баланс выживания: день победы, штрафы морали за смерть, строки штрафов голода/жажды по дням, урон от холода, кулдауны.
- `CommandantCommentSettings` — шаблоны комментариев коменданта (смерти, голод, жажда, ранения, спокойствие).

**Связи данных (кратко):**
- `ResourceManager` читает/пишет `ResourceData`.
- `CharacterManager` → `ResourceManager` (списание/выдача ресурса при пайке).
- `ExpeditionManager` → `ResourceManager` (награды), → `CharacterManager` (кто на вылазке).
- `EventManager` → `ResourceManager` + `CharacterManager` (эффекты опции записи).
- `DayCycleManager` собирает `NightReportData` от всех систем ночью.

## 4. Данные и логика: разделение (состояние на момент начала ТЗ)

- **Вынесены в SO:** параметры локаций вылазок, записок, черт, профиля генерации, комментариев коменданта.
- **Частично вынесены:** баланс выживания в `SurvivalConfig` (штрафы голода/жажды, холода, день победы).
- **Жёстко задано в коде (требует рефакторинга для уровня «Средний»):**
  - `ElectricalPanelController`: `baseBreakdownChancePercent = 15`, `baseRepairSuccessChancePercent = 60`, `baseRepairInjuryChancePercent = 25`, `repairFailureDamageHP = 15`, `breakdownChanceForOnePerson = 60`, reducción за человека и т.д.
  - `DayCycleManager`: `VictoryDay = 10` (через `SurvivalConfig`, но fallback 10), штрафы за死亡 через `SurvivalConfig` или fallback.
  - `ExpeditionManager`: `referencePopulation = 5`, увеличение шансов смерти/травмы заmissing person = 5%.
  - `ResourceManager`: стартовые ресурсы (еда 8–10, вода 8–10, топливо 4–6) заданы в `Awake()`.
- **Нет явной системы сохранения** — состояние живёт в памяти, при перезапуске сцены сбрасывается.

## 6. Выводы для выполнения ТЗ

| Уровень ТЗ | Что нужно сделать | Статус / план |
|------------|-------------------|---------------|
| **Начальный (≤30)** | Архитектурный граф, блок-схема, схема данных; полный центральный цикл от действия игрока до результата | Документы уже есть и верны — оформить как отчёт уровня 1 |
| **Средний (≤70)** | Декомпозиция + разделение данных от логики; параметры → конфиги; структура + заполненный пример; kontrolled-реакция на ошибочные/граничные данные без разрушения состояния | Рефакторинг: `GameBalanceConfig` (SO), валидация, защита от некорректных данных |
| **Высший (≤100)** | Независимость модулей + расширение через данные; добавить элемент существующего типа через данные без изменения кода; инструкция, исходный/изменённый данные, новый элемент в игре | Новые SO-ассеты (локация, черта, записка) + пример подключения без кода |
