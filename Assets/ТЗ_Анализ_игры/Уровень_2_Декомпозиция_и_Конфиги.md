## 1. Декомпозиция и разделение данных от логики

### Что было до изменений
Многие числовые параметры были **захардкожены в телах скриптов** менеджеров:
- `ResourceManager.Awake()` — стартовые ресурсы (еда 8–10, вода 8–10, топливо 4–6) заданы константами в коде.
- `DayCycleManager` — `VictoryDay = 10`, запасной штраф морали `baseMoralePenaltyPerDeathFallback = 10`.
- `ElectricalPanelController` — `baseBreakdownChancePercent = 15`, `baseRepairSuccessChancePercent = 60`, `baseRepairInjuryChancePercent = 25`, `repairFailureDamageHP = 15`, `breakdownChanceForOnePerson = 60` и т.д.
- `ExpeditionManager` — `referencePopulation = 5`, увеличение шанса смерти/травмы заmissing person = 5%.

### Что сделано (Уровень 2)

Создан отдельный класс **GameBalanceConfig** (`Scripts/Core/GameBalanceConfig.cs`) — ScriptableObject, который выносит все числовые параметры баланса из кода в данные:

| Группа параметров | Где был хардкод | Где теперь (GameBalanceConfig) |
|-------------------|-----------------|--------------------------------|
| Стартовые ресурсы | `ResourceManager.Awake()` | `startFoodMin/Max`, `startWaterMin/Max`, `startFuelMin/Max` |
| День победы | `DayCycleManager.VictoryDay` | `victoryDay` |
| Штраф морали за смерть | `DayCycleManager.BaseMoralePenaltyPerDeath` | `baseMoralePenaltyPerDeath` |
| Поломка генератора | `ElectricalPanelController` | `baseBreakdownChancePercent`, `breakdownChanceForOnePerson`, `breakdownReductionPerAdditionalPerson` |
| Ремонт генератора | `ElectricalPanelController` | `baseRepairSuccessChancePercent`, `baseRepairInjuryChancePercent`, `repairFailureDamageHP`, `repairSuccessBonusPerAdditionalPerson` |
| Вылазки (численность) | `ExpeditionManager` | `referencePopulation`, `expeditionDeathChanceIncreasePerMissingPerson`, `expeditionInjuryChanceIncreasePerMissingPerson` |

**Механизм подключения:**
- Каждый менеджер имеет сериализуемое поле `balanceConfig` (тип `GameBalanceConfig`).
- Читаемые свойства (`BaseBreakdownChancePercent`, `ReferencePopulation` и т.д.) отдают значение из `balanceConfig`, если он назначен — иначе используют сериализованное Inspector-поле как фолбэк.
- Dadurch-existing настройки в инспекторе сцены не ломаются, а новый конфиг можно подключить в один клик.

**Пример заполненного конфига:** `Resources/GameBalanceConfig.asset` (YAML, см. раздел 5).

### Ответственность, входы и выходы модулей (после декомпозиции)

| Модуль | Ответственность | Входы (зависимости) | Результаты / выходы | Где настраивается |
|--------|----------------|---------------------|---------------------|-------------------|
| ResourceManager | Единое хранилище ресурсов, валидация consumo/add | `ResourceData`, `GameBalanceConfig` (старт) | `Consume*/Add*` → bool, `OnResourcesChanged` | `balanceConfig` (стартовые ресурсы) |
| CharacterManager | Список жителей, рационы, карточки | `CharacterGenerator`, `ResourceManager` | `CreateCharacter`, `SetRation`, `ResetDailyRations`, `OnRationsChanged` | — |
| CharacterGenerator | Генерация одного персонажа | `CharaterObject`, `NamePool`, `Trait` | `GeneratedCharacter` | `CharaterObject` (SO) |
| DayCycleManager | Оркестратор ночи, победа/поражение | Все менеджеры, `SurvivalConfig`, `GameBalanceConfig` | `NightReportData`, `OnDayChanged/Defeat/Victory` | `balanceConfig` (день победы, штраф смерти) |
| ExpeditionManager | Вылазки, риски, кулдауны | `CharacterManager`, `DayCycleManager`, `ResourceManager`, `GameBalanceConfig` | `TryStartExpedition`, `ProcessCompletedDay`, `OnExpeditionsChanged` | `balanceConfig` (база人口, шансы смерти/травмы) |
| ElectricalPanelController | Генератор, поломка, ремонт | `ResourceManager`, `CharacterManager`, `ExpeditionManager`, `GameBalanceConfig` | `ToggleGenerator`, `SendCharacterForRepair`, `ProcessGeneratorNight` | `balanceConfig` (шансы поломки/ремонта/травмы) |
| EventManager | Записки у двери, опции | `DayCycleManager`, `DoorNoteData` (SO), `ResourceManager`, `CharacterManager` | `ApplyOption` — меняет ресурсы, мораль, HP, спавн | `DoorNoteData` (SO) |

## 2. Типовой сценарий взаимодействия модулей

**Сценарий: игрок выдаёт пайк еды персонажу днём, потом ложится спать, ночью происходит расчёт выживания.**

```
1. Игрок кликает по рациональной доске → InteractRationBoard.Interact()
   → RationMenuUI.Open()

2. Игрок переключает toggle «Еда» для персонажа →
   CharacterManager.SetFoodRation(character, true)
     └─ CanChangeRation(character) → жив, не в вылазке, в списке? → да
     └─ ResourceManager.Instance.ConsumeFood(1) → достаточно еды? → да
     └─ character.consecutiveFoodDays++, receivesFoodToday = true
     └─ OnRationsChanged() → RationMenuUI.RefreshResourceCounts() + карточки

3. Игрок кликает по кровати → InteractBed.Interact() → SleepSequence()
   → отключение PlayerMove/Interactor → затухание → DayCycleManager.StartNextDay()

4. Ночные расчёты (DayCycleManager):
   4.1 Топливо/температура → ResourceManager.ConsumeFuel / AddTemperature
   4.2 UpdateSurvivalCounters → для каждого жителя: дни без еды/воды → штрафы HP/мораль,
         возможная смерть; холод → урон; восстановление HP/морали при пайках ≥2 дней
   4.3 ResetDailyRations → сброс receivesFoodToday/WaterToday
   4.4 ExpeditionManager.ProcessCompletedDay → проверка активных вылазок
   4.5 ElectricalPanelController.ProcessGeneratorNight → поломка/ремонт генератора
   4.6 ApplyDeathMoralePenalty → штраф морали за смерти
   4.7 ProcessMoraleDepartures → уход при мораль < 0
   4.8 OnDayChanged → EventManager.OnNewDay → записка на следующий день
   4.9 IsDefeat()/IsVictory() → OnDefeat/OnVictory

5. Утро: MorningReportPanel.Show(NightReportData) → игрок видит результат ночи
   → нажатие «Продолжить» → возврат управления игроку → следующий день
```

**Места настройки:** все числовые баланс-параметры now в `GameBalanceConfig.asset`; локации вылазок, записи, черты, профиль персонажей — в отдельных `.asset`-файлах ScriptableObject.

## 3. Структура и заполненный пример конфига

Файл: `Assets/Resources/GameBalanceConfig.asset` (текстовый YAML).

Структура (поля `GameBalanceConfig`):
```
startFoodMin/Max        — диапазон банок еды при старте (по умолчанию 8–10)
startWaterMin/Max       — диапазон бутылок воды при старте (по умолчанию 8–10)
startFuelMin/Max        — диапазон канистр топлива при старте (по умолчанию 4–6)
victoryDay              — день победы (по умолчанию 10)
baseMoralePenaltyPerDeath — штраф морали за смерть (по умолчанию 10)
baseBreakdownChancePercent — базовый шанс поломки генератора % (15)
breakdownChanceForOnePerson — шанс поломки при 1 человеке в бункере % (60)
breakdownReductionPerAdditionalPerson — снижение шанса поломки за человека % (10)
baseRepairSuccessChancePercent — базовый шанс ремонта % (60)
baseRepairInjuryChancePercent — базовый шанс травмы при ремонте % (25)
repairFailureDamageHP   — урон HP при неудачном ремонте (15)
repairSuccessBonusPerAdditionalPerson — бонус ремонта за человека % (10)
referencePopulation     — базовая численность для вылазок (5)
expeditionDeathChanceIncreasePerMissingPerson — +% смерти за missing person (5)
expeditionInjuryChanceIncreasePerMissingPerson — +% травмы за missing person (5)
```

## 4. Контролируемая реакция на ошибочный и граничный набор данных

Ниже перечислены boundary/erroneous сценарии, с которыми код справляется **без разрушения состояния** (игра не ломается, состояние остаётся консистентным).

| # | Сценарий (ошибочный/граничный набор данных) | Где обрабатывается | Реакция (что происходит) | Состояние после |
|---|---------------------------------------------|---------------------|--------------------------|-----------------|
| 1 | Попытка выдать пайк еды, когда на складе 0 банок | `ResourceManager.ConsumeFood` → `CharacterManager.SetFoodRation` | `ConsumeFood(1)` возвращает `false`; пайк не выдаётся; `OnRationsChanged` не вызывается | Ресурсы не меняются, персонаж остаётся без пайка, игра продолжается |
| 2 | Попытка добавить отрицательное количество ресурса | `ResourceManager.Add(ref int, int)` | `amount < 0` → метод возвращается без изменений | Ресурс не меняется |
| 3 | Попытка потребовать больше ресурса, чем есть | `ResourceManager.Consume(ref int, int)` | `resource < amount` → возвращает `false` | Ресурс не меняется |
| 4 | `GameBalanceConfig` не назначен в инспекторе менеджера | Все менеджеры через свойства-фолбэки | Используются сериализованные Inspector-значения (старые значения по умолчанию) | Игра работает со старыми значениями баланса |
| 5 | `SurvivalConfig` не назначен | `DayCycleManager.Awake()` → `Resources.LoadAll<SurvivalConfig>`; иначе fallback | `VictoryDay = 10`, `BaseMoralePenaltyPerDeath = 10` (fallback) | Игра работает с дефолтными значениями |
| 6 | Персонаж `null` или `isDead`/`isExiled` в ночных расчётах | `DayCycleManager.UpdateSurvivalCounters` → `continue` | Персонаж пропускается, не участвует в расчётах выживания | Состояние живых персонажей не затрагивается |
| 7 | Попытка отправить на вылазку персонажа, который уже в вылазке | `ExpeditionManager.TryStartExpedition` → `IsCharacterOnExpedition` | Возвращает `false` с сообщением «Уже на вылазке» | Вылазка не создаётся, текущие вылазки не меняются |
| 8 | Превышен лимит одновременных вылазок | `ExpeditionManager.TryStartExpedition` → `ActiveExpeditionCount >= MaxConcurrent` | Возвращает `false` с сообщением о лимите | Новая вылазка не запускается |
| 9 | Локация на кулдауне или уже в поездке | `ExpeditionManager.IsLocationAvailable` | Возвращает `false`; UI показывает причину | Вылазка не начинается |
| 10 | Температура выходит за 0–3 | `ResourceManager.SetTemperature` | `Mathf.Clamp(level, 0, 3)` | Температура фиксируется в допустимом диапазоне |
| 11 | Генератор сломан, попытка включить | `ElectricalPanelController.ToggleGenerator` → `CanTurnOnGenerator` | Отказ с сообщением, генератор не включается | Состояние генератора не меняется |
| 12 | Ремонт генератора, когда он не сломан | `SendCharacterForRepair` → `!GeneratorBroken` | Возвращает `false`, ремонт не ставится в очередь | Очередь ремонта не меняется |

### Пример проверки (сценарий 1) — пошагово

1. На складе 0 банок еды (`resourceData.foodCans == 0`).
2. Игрок пытается выдать пайк персонажу.
3. `CharacterManager.SetFoodRation(character, true)` → `CanChangeRation` проходит.
4. `ResourceManager.Instance.ConsumeFood(1)` → `Consume(ref foodCans, 1)` → `0 < 1` → возвращает `false`.
5. `SetFoodRation` возвращает `false`; `receivesFoodToday` остаётся `false`; `consecutiveFoodDays` не меняется; `OnRationsChanged` не вызывается.
6. Игрок видит в UI сообщение «Недостаточно еды» (реализовано в `RationMenuUI`).
7. Ночь наступает normal: персонаж получает штраф за день без еды (см. `SurvivalConfig.hungerPenalties`), но состояние игры не разрушено.

### Валидация конфига

`GameBalanceConfig.Validate()` вызывается в `OnValidate()`/`OnEnable()` и проверяет:
- `min <= max` для диапазонов стартовых ресурсов;
- `victoryDay >= 1`;
- все процентные значения в диапазоне 0–100;
- `repairFailureDamageHP` в 0–100;
- `referencePopulation >= 1`.

При некорректных значениях они clamp'ятся к допустимому диапазону и пишется `Debug.LogWarning` — игра продолжает работу.
