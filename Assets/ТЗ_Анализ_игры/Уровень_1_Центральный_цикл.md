## 1. Архитектурный граф

Полный граф см. в [`Assets/GameArchitecture_Complete.md`](../../GameArchitecture_Complete.md).

Кратко — слои и связи:

```
Игрок (мышь/клавиатура)
   │
   ▼
Ввод: Interactor (raycast) → IInteractable.Interact() на объекте мира
   │
   ├── Дверь/записка  → EventManager (записка) → DoorNoteUI → ApplyOption → ResourceManager / CharacterManager
   ├── Кровать        → DayCycleManager.StartNextDay() → ночь → утро → следующий день
   ├── Рационная доска→ RationMenuUI → CharacterManager.SetFoodRation/SetWaterRation → ResourceManager
   ├── Электропанель  → ElectricalPanelUI → ElectricalPanelController (генератор/ремонт)
   └── ПК             → Cinemamine камера + панель вылазок → ExpeditionManager.TryStartExpedition
```

Все менеджеры — синглтоны на GameObject `Manager`; данные — `ScriptableObject` + сериализуемые классы; обмен — через C#-события (`Action`) и прямые вызовы.

## 2. Блок-схема алгоритма

Полная блок-схема см. в [`Assets/GameAlgorithm_Flowchart.md`](../../GameAlgorithm_Flowchart.md).

Порядок выполнения:
1. **Инициализация** — синглтоны менеджеров, генерация 5 стартовых персонажей (`CharacterGenerator`), случайные стартовые ресурсы (`ResourceManager`).
2. **Дневной цикл** — игрок перемещается, подсветка объектов, клик → взаимодействие с объектом (ветвление по типу объекта).
3. **Сон** — кровать → `SleepSequence()` → отключение управления → затухание экрана → `StartNextDay()`.
4. **Ночные расчёты** (8 шагов):
   1. Топливо и температура (генератор работает → −1 топливо, +1 температура; иначе −1 температура).
   2. Выживание персонажей (голод/жажда/холод → штрафы мораль/HP, смерть, лечение при пайках ≥2 дней подряд).
   3. Сброс пайков на новый день.
   4. Экспедиции (уменьшение дней, завершение → смерть/травма/награды).
   5. Генератор (ночная поломка, ремонт).
   6. Мораль и уходы (штраф за смерти, уход при мораль < 0).
   7. События дня (записки EventManager).
   8. Проверка конца игры: поражение (все мертвы/ушли) или победа (день ≥ 10).
5. **Утренняя сводка** — `MorningReportPanel` показывает `NightReportData` + комментарий коменданта.
6. **Возврат в день** — обратное затухание, управление возвращается игроку.

Ключевые ветвления: нехватка ресурса при пайке (отказ без разрушения состояния), недоступность локации/персонажа для вылазки, исход вылазки (смерть/травма/успех), ремонт генератора (успех/неудача/травма), конец игры, комментарий коменданта.

## 3. Схема данных

Полная схема см. в [`Assets/GameDataSchema.md`](../../GameDataSchema.md).

Главные сущности и поля:
- `ResourceData` — еда, вода, топливо, день, температура, генератор сломан/вкл.
- `GeneratedCharacter` — пол, имя, возраст, портрет, HP/мораль 0–100, дни без еды/воды, флаги рационов, `isDead`/`isExiled`, черты.
- `NightReportData` — агрегат ночи (день, температура, изменения ресурсов, выживание, смерти, уходы, экспедиции, события).
- `ExpeditionLocationData` (SO) — локация: длительность, шансы травмы/смерти, урон, кулдаун, награды.
- `DoorNoteData` (SO) — записка: тип появления, день, шанс, текст, опции с дельтами.
- `Trait` (SO) — черта с эффектами (модификаторы генератора, ремонта, вылазок).
- `SurvivalConfig` (SO) — баланс выживания (день победы, штрафы голода/жажды/холода).

## 4. Назначение модулей, входы, результаты, обмен данными

| Модуль | Ответственность | Входы | Результаты / выходы | Обмен данными |
|--------|----------------|-------|---------------------|---------------|
| Interactor | Луч взаимодействия от камеры | Камера, мышь, объекты с IInteractable | Вызов Interact(), Highlight() | Прямые вызовы объектов мира |
| ResourceManager | Хранилище ресурсов | ResourceData | Consume/Add/Set/… возвращают bool | Событие OnResourcesChanged |
| CharacterManager | Жители и рационы | CharacterGenerator, ResourceManager | CreateCharacter, SetRation, ResetDailyRations | Событие OnRationsChanged |
| DayCycleManager | Оркестратор ночи | Все менеджеры, SurvivalConfig | NightReportData, OnNightComplete/Defeat/Victory | События + прямые вызовы |
| ExpeditionManager | Вылазки | CharacterManager, DayCycleManager, ResourceManager, ExpLocationData | TryStartExpedition, ProcessCompletedDay | Событие OnExpeditionsChanged |
| ElectricalPanelController | Генератор и ремонт | ResourceManager, CharacterManager, ExpeditionManager, Trait | ToggleGenerator, SendCharacterForRepair, ProcessGeneratorNight | События OnResourcesChanged / OnGeneratorStatusChanged |
| EventManager | Записки у двери | DayCycleManager, DoorNoteData (SO), ResourceManager, CharacterManager | ApplyOption меняет ресурсы, мораль, HP, спавн жителя | Прямые вызовы менеджеров |

## 5. Проверка: центральный цикл от действия до результата

Пройдём по реальному коду (все скрипты прочитаны):

1. Игрок наводит курсор на кровать → `Interactor.Update()` делает raycast, при клике `InteractBed.Interact()` → `SleepSequence()`.
2. `SleepSequence` отключает `PlayerMove`/`Interactor`, затухает экран, вызывает `DayCycleManager.StartNextDay()`.
3. `StartNextDay()` запускает 8 шагов ночи, каждый модуль вносит свой вклад в `NightReportData`.
4. После ночи `OnDayChanged` → `EventManager.OnNewDay` выбирает записку на следующий день.
5. `OnNightComplete` → `MorningReportPanel.Show(report)` — игрок видит результат ночи.
6. Проверка `IsDefeat()`/`IsVictory()` → экран поражения/победы (`DefeatScreenPanel`): перезапуск сцены или выход.

Центральный цикл реализован полностью, от действия игрока (клик по объекту) до результата (утренняя сводка / конец игры).
